# 01: Inject preview-only env vars from a script

**Category:** enhancement
**Status:** needs-triage

Raised in review of ticket 05 (comment on `.github/workflows/preview-environments.yml`, the `VITE_SCAN_ENABLED` step).

Each preview-only Vercel env var (today `VITE_SCAN_ENABLED`) is a hand-written step in `.github/workflows/preview-environments.yml` that runs `vercel env add ... preview "$HEAD_REF"`, plus a matching removal on cleanup. Adding another one means editing the workflow file.

Idea: a script (for example `scripts/preview-env/inject.sh`) that reads a small list of preview-only variables and adds or removes them for the branch, so the workflow calls it once and a new preview-only variable is a one-line change to the list. Not scheduled; triage when a second preview-only variable appears.
