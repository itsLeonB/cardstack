## Agent Brief

**Category:** bug
**Summary:** Currently, the `/login` and `/register` routes in the frontend are accessible to users who are already logged in (authenticated). Authenticated users visiting these guest routes should be redirected to the home page (`/`).

**Current behavior:**
- `frontend/src/routes/login.tsx` and `frontend/src/routes/register.tsx` do not define a `beforeLoad` route guard.
- When an authenticated user with a valid session cookie navigates to `/login` or `/register`, the route renders the login or registration forms without checking `GET /auth/me`.

**Desired behavior:**
1. Create a `requireGuest` route guard in `frontend/src/lib/route-guard.ts` that probes `GET /auth/me` via `context.queryClient.ensureQueryData(getGetCurrentUserQueryOptions())`.
2. If `GET /auth/me` returns `status: 200` (authenticated), throw a TanStack Router redirect to `/` (`to: "/"`).
3. If `GET /auth/me` returns any non-200 status (e.g. `401`), allow navigation to proceed.
4. Attach `beforeLoad: requireGuest` to `frontend/src/routes/login.tsx` and `frontend/src/routes/register.tsx`.
5. Add unit test coverage in `frontend/src/lib/route-guard.test.ts` verifying `requireGuest` redirects authenticated users to `/` and permits unauthenticated visitors.
6. Add Playwright e2e test coverage in `frontend/e2e/guest-redirect.spec.ts` (or similar) verifying that an authenticated user navigating to `/login` or `/register` is redirected to `/`.

**Acceptance criteria:**
- [ ] `requireGuest` guard function added to `frontend/src/lib/route-guard.ts`.
- [ ] `frontend/src/routes/login.tsx` and `frontend/src/routes/register.tsx` use `beforeLoad: requireGuest`.
- [ ] Authenticated users navigating to `/login` or `/register` are redirected to `/`.
- [ ] Unauthenticated users can access `/login` and `/register` normally.
- [ ] Unit tests in `frontend/src/lib/route-guard.test.ts` cover `requireGuest` behavior.
- [ ] All frontend unit tests (`bun run test`), linter (`bun run lint`), and typecheck (`bun run typecheck`) pass cleanly.
