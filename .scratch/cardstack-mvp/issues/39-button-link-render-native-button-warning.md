# 39: `Button` rendered as a link logs a Base UI `nativeButton` warning

**Category:** bug
**Status:** resolved

**Blocked by:** None (can start immediately)

## Agent Brief

**Category:** bug
**Summary:** Every `<Button render={<Link … />}>` logs "A component that acts as a button expected a native `<button>` because the `nativeButton` prop is true" in the dev console. Fix it in the shared `Button` so links keep native link semantics.

**Current behavior:**
- The shared `Button` wraps Base UI's `ButtonPrimitive`, which defaults `nativeButton` to `true`. Base UI's dev-only check in `useButton` warns when that is true and the rendered element is not a `<button>`.
- 11 call sites render a router `Link` through `Button`'s `render` prop: the collections index, the guest landing page (3), the dashboard (4), the not-found page (2) and the collection card (1). Each logs the warning.
- Verified from the code path in `@base-ui/react` 1.8; not yet reproduced in a browser.
- The call sites that pass `<Button/>` as the `render` of a Base UI trigger (alert dialog, user menu, theme toggle, delete-collection dialog) render a real `<button>` and are not affected.

**Desired behavior:**
- No Base UI `nativeButton` warning in the dev console on the home, collections and not-found pages.
- A `Button` rendered as a link stays an `<a>` with link semantics: it must NOT gain `role="button"`.
- A `Button` that renders a real `<button>` (the default, and the trigger case) behaves exactly as today.

**Key interfaces:**
- Fix inside the shared `Button` component, so the 11 call sites need no change. When `render` supplies a link, `Button` applies only the `buttonVariants` styling to it and skips `ButtonPrimitive`'s button behaviour. `Button` has to tell a link render from a button render; pick the simplest reliable way.
- Do NOT fix this by passing `nativeButton={false}` to `ButtonPrimitive`. Base UI's `useButton` then adds `role="button"` to the `<a>`, so navigation links announce as buttons to screen readers.

**Acceptance criteria:**
- [x] No Base UI `nativeButton` warning is logged on the home (guest and signed-in), collections index and not-found pages
- [x] A link-rendered `Button` has no `role="button"` and still navigates with Enter and a click
- [x] A `Button` used as a Base UI trigger's `render` still renders a `<button>` with no new warning
- [x] A frontend test covers the link-rendered case (element is an `<a>`, no `role="button"`); both verification scripts pass

**Out of scope:**
- Migrating call sites to a separate `LinkButton` component
- Any other Base UI warnings
