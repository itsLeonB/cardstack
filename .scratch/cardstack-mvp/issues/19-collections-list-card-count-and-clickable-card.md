# 19: Collections list: show card count and make the whole card clickable

**Category:** enhancement
**Status:** done — implemented (backend `670a6a4`, `8f29a60`; frontend `461e0a1`, `c3a175a`, `6b89562`) on `feat/collections-card-count-clickable-card`, merged to `main` via PR #26 (`0064b59`), verified.

**Blocked by:** None (can start immediately)

## Agent Brief

**Category:** enhancement
**Summary:** Each Collection on the Collections page shows how many cards it holds, and the whole Collection card navigates to its detail page instead of only the title.

**Current behavior:**
- The Collection response carries `id`, `title`, `description` and `maxCardCount`, with no card count.
- On the Collections list page only the Collection title is a link to the detail page. The rest of the card is inert.

**Desired behavior:**
- Every Collection in the list (and in the single-Collection response, so the detail page can reuse it) reports `cardCount`: the summed quantity of all its Inventory Entries. This is the same measure the capacity limit uses, not the number of distinct Cards. An empty Collection reports `0`.
- The Collections page renders the count on each Collection card, for example "37 cards" (singular for exactly 1).
- Clicking anywhere on a Collection card navigates to that Collection's detail page. The existing edit and delete actions on the card remain independently clickable and must not trigger navigation. The card is reachable and activatable by keyboard, and has one accessible name.
- After Inventory Entries change (any add, update or remove), the list shows the fresh count on next view; a stale cached count must not survive.

**Key interfaces:**
- The Collection response DTO gains `cardCount` (integer). The computation is an aggregate, so it needs a repository-level query; follow the backend conventions for a custom repository that wraps `crud.Repository` and reads via `GetGormInstance`, and avoid an N+1 query per Collection on the list endpoint.
- Regenerate `openapi.json` and the frontend generated client.
- The Collections list route/component and its Collection card component.

**Acceptance criteria:**
- [ ] `GET /collections` and `GET /collections/{id}` include `cardCount` equal to the summed Inventory Entry quantity, `0` when empty
- [ ] Listing N Collections runs a constant number of queries (no per-Collection query)
- [ ] A service unit test (mocked repository) and a real-Postgres repository test cover the count, including an empty Collection and a Collection with several entries of quantity above 1
- [ ] Each Collection card on the list page displays its count
- [ ] Clicking any non-action area of a Collection card navigates to its detail page; clicking edit or delete does not navigate
- [ ] The card is keyboard-focusable and activates on Enter
- [ ] A frontend test covers the count display and the navigation behavior
- [ ] Backend and frontend verification scripts pass

**Out of scope:**
- Showing the count against the capacity limit (for example "37 / 100")
- Distinct-card counts
- Any change to the detail page layout (tickets 21 and 22)
