# 37: Catalog quantities lookup per loaded page

**Category:** bug
**Status:** ready-for-agent

**Blocked by:** 33, 36

Findings: `.scratch/cardstack-mvp/research/virtualized-infinite-scroll.md` (section 5). Related ticket: 23.

## Agent Brief

**Category:** bug
**Summary:** On the catalog, the "in this Collection" quantities must stay correct for every loaded tile once the list grows past one page.

**Current behavior:**
The catalog looks up the quantities for all displayed card ids in one request with a limit equal to the id count, and the endpoint caps the limit at 100. With infinite scroll the id list grows past 100, so tiles beyond the cap would show no quantity.

**Desired behavior:**
- Quantities are looked up per loaded page (one query per page, at most 100 ids each) and merged for display.
- Saving a quantity change patches the matching page's lookup in the cache from the bulk update result (the saved-results callback from ticket 36), so a stale value never reappears.
- Ticket 23's behaviour (adding to a Collection from the catalog, debounced saves, pending-edit protection) is unchanged.

**Key interfaces:**
- The catalog's quantity lookup and the card results component that merges it into the tiles.
- `useQuantityBatch`'s saved-results callback.

**Acceptance criteria:**
- [ ] With more than 100 cards loaded, every tile shows its correct quantity
- [ ] Editing a quantity and saving keeps the saved value as further pages load
- [ ] Existing ticket 23 tests still pass; a test covers the over-100 case
- [ ] Both verification scripts pass

**Out of scope:**
- Raising the endpoint's 100-id cap
- Collection entries and Master Inventory (ticket 36)
