## Agent Brief

**Category:** bug
**Summary:** When cards are added to a Collection from the catalog in one browser tab, the Collection detail page already open in another tab refreshes its filters but not its card list when the user returns to it.

**Current behavior:**
- Reported: open the catalog in one tab and add cards to a Collection, then switch to another tab showing the Collection detail page. The filter options update but the card list does not; a manual refresh is needed.
- Cause (found by reading the code, not reproduced in a browser): in `frontend/src/components/collections/collection-entries.tsx` the entries query sets `refetchOnWindowFocus: false` (added in `d670f20`). The facets query on the same page uses the default and refetches on window focus. A fresh mount is fine (`refetchOnMount: "always"`, `gcTime: 0`).

**Desired behavior:**
- Returning focus to the Collection detail tab refetches the entries list, so cards added elsewhere appear.
- The refetch is skipped while the user has unsent or in-flight quantity edits (`useQuantityBatch` has pending changes), so optimistic values and a flush in progress are never disturbed.
- Accepted trade-off (agreed with the maintainer): a card the user reduced to 0 in this tab disappears from the list when a focus refetch runs, since returning to the tab counts as returning to the page. This refines the ticket 22 rule "stays at 0 until reload or leaving and returning".

**Key interfaces:**
- The entries query options in `CollectionEntries` (focus refetch conditional on no pending edits) and `useQuantityBatch`'s pending state.
- The catalog's `CollectionCardResults` entries query already uses default focus refetching; leave it unless it conflicts.

**Acceptance criteria:**
- [ ] With the Collection page open, adding a card to the Collection elsewhere and refocusing the tab shows the new card without a manual refresh
- [ ] A focus refetch does not run while quantity edits are pending or being saved, and pending optimistic values survive
- [ ] A test covers the focus refetch with and without pending edits; the existing `refetchOnMount`/`gcTime` assertions still hold
- [ ] Both verification scripts pass

**Out of scope:**
- Cross-tab live sync (BroadcastChannel, polling or websockets)
- Changes to the catalog page's entries query
