# 16: Apply global CSRF guard middleware with auth endpoint exemptions

> *This was generated by AI during triage.*

**Category:** enhancement
**Status:** ready-for-agent

**Blocked by:** None (can start immediately)

## Agent Brief

**Category:** enhancement
**Summary:** Currently CSRFGuard is only applied manually on select routes (/auth/logout and /auth/refresh). Data-mutating routes like /collections (POST, PUT, DELETE) lack CSRF protection. CSRFGuard should be applied globally across all Huma endpoints using Huma's api.UseMiddleware(...), while exempting unauthenticated initial auth endpoints (/auth/login and /auth/register) where the client does not yet possess a csrf_token cookie.

**Current behavior:**
CSRFGuard is defined in `backend/internal/adapters/http/auth/middleware.go` and manually attached to logout/refresh operations inside `auth_handler.go`. Routes registered via `endpoint.RegisterAll`, such as `collectionHandler.Routes()` in `routes/register_routes.go`, are wrapped only with `sessionGuard` and lack CSRF double-submit validation. Mutating requests (POST/PUT/DELETE) on collections do not check for the `X-CSRF-Token` header.

**Desired behavior:**
1. Update `CSRFGuard` in `backend/internal/adapters/http/auth/middleware.go` (or wrap it) to support path exemptions (specifically `/auth/login` and `/auth/register`). Safe HTTP methods (`GET`, `HEAD`, `OPTIONS`) continue to be skipped as `CSRFGuard` currently does.
2. Register `CSRFGuard` globally on Huma `api` (e.g. in `backend/internal/adapters/http/routes/register_routes.go` or `server.go`) using `api.UseMiddleware(...)` so that all current and future mutating endpoints automatically enforce CSRF double-submit checks (`X-CSRF-Token` header matching the `csrf_token` cookie).
3. Remove manual per-route `CSRFGuard` attachments in `backend/internal/adapters/http/handler/auth_handler.go`.
4. Add HTTP route tests in `backend/internal/adapters/http/routes/collection_routes_test.go` and `auth_routes_test.go` verifying:
   - Mutating collection endpoints (`POST /collections`, etc.) reject requests with `403 Forbidden` if `X-CSRF-Token` is missing or invalid.
   - Mutating collection endpoints succeed when valid `X-CSRF-Token` header and session cookies are supplied.
   - Unauthenticated routes `/auth/login` and `/auth/register` remain accessible without a CSRF token.

**Acceptance criteria:**
- [ ] `CSRFGuard` is registered globally on Huma `api`.
- [ ] `/auth/login` and `/auth/register` are exempted from `CSRFGuard` validation.
- [ ] Mutating routes on `/collections` enforce CSRF double-submit header validation.
- [ ] Redundant manual `CSRFGuard` wrappers are removed from `auth_handler.go`.
- [ ] All backend route tests pass cleanly.
