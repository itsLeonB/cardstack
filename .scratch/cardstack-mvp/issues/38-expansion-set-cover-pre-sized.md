## Agent Brief

**Category:** enhancement
**Summary:** Replace the read-time Cloudflare transformation of Expansion Set covers with a once-only resize at host time, done from the originals already in R2 (never re-downloaded from pokemonasia). Decision and rationale are in ADR-0017; this ticket does not re-open them. Cards keep their original-size, read-time behavior (ADR-0016).

**Current behavior:**
Each `ExpansionSet` row has `SourceImageURL` (the scraped pokemonasia address) and `ImageKey` (the hosted original at `expansion-sets/<id>`, uploaded `immutable`). The API builds `imageUrl` from `ImageKey`, and the frontend turns it into `/cdn-cgi/image/width=128,format=auto,onerror=redirect/<key>` through the `setCover` variant in `frontend/src/lib/image.ts`. A cover is only ever shown at 64px CSS in `ExpansionSetTile`; no view shows it larger.

**Desired behavior:**
1. A new Go command, `cmd/presize-images` (plus a Makefile target), finds every Expansion Set with a non-empty `ImageKey` and an empty `CoverKey`, reads the original from R2, resizes it so its longest side is 128px, encodes WebP with alpha, uploads it as `expansion-sets/<id>.<hash8>.webp` (hash of the output bytes, so the one-year `immutable` cache stays safe if the size is ever changed) and stores the key in the new `CoverKey`. The resize shells out to `vips`; the command checks for `vips` first and exits with a clear message if it is missing. The original object and `ImageKey` are left untouched as the source for any later re-size. It is idempotent, uploads with `Content-Type: image/webp` and the same `Cache-Control: public, max-age=31536000, immutable` the other hosting commands use, needs the four `R2_*` settings the other hosting commands use, logs and retries-next-run any failure, and exits non-zero if any row failed (the `host-images` pattern). A `-set <code>` flag restricts it to one set, like `host-images`.
2. `ExpansionSet` gains `CoverKey string`, `gorm:"not null;default:''"`, with a migration. The ingester and `host-images` are unchanged: they keep hosting the original and leave `CoverKey` empty, and `presize-images` is the second step.
3. Every address the API exposes for an Expansion Set cover is built from `CoverKey`, empty when it is empty. There is no fallback to `ImageKey` or to the source address (ADR-0016's no-silent-fallback rule). The sites to change: `ToExpansionSetSummary` in `backend/internal/domain/mapper/catalog_mapper.go` (also feeds `SeriesSummary.ExpansionSets` and the facet option's embedded summary); `ToCardSummary` in the same file, which builds the embedded `ExpansionSet` inline from `CardResult.ExpansionSetImageKey`. That field is the only other place: it is declared in `backend/internal/domain/repository/catalog_repository.go` (around line 260) and filled by a raw select alias (`expansion_sets.image_key AS expansion_set_image_key`, around line 279), so a missed rename compiles and silently returns an empty cover. Switch both to `cover_key`, and add a repository test that fails if a card result's set cover is empty when `cover_key` is set. Re-run `grep -rnE 'ExpansionSetImageKey|expansion_set_image_key' backend/` at the end to confirm nothing else reads the set's `image_key` for display.
4. Frontend: remove the `setCover` variant from `imageSources()` and make `ExpansionSetTile` use `imageUrl` directly (no `/cdn-cgi/` rewrite). Keep the existing behavior for an empty address or a failed load: the tile renders text-only, no broken-image icon, no layout shift. Card variants are untouched. The implementation follows the `accessibility` and `frontend-design` skills.
5. Update `docs/agents/deployment/images.md`: the new command, the `vips` requirement, the `cover_key` column, that `imageUrl` for Expansion Sets now comes from it, and that the `setCover` rewrite is gone.

**Rollout order (put this in the PR description and in `images.md`):**
1. Apply the migration with `make job` against the production database (a goose SQL file under `backend/internal/adapters/db/postgres/migrations/`, run separately from the API, per `images.md`). It only adds `cover_key` (empty, `not null default ''`), so the running API keeps working because it still reads `image_key`. Do not drop or rename anything in this migration.
2. Run `presize-images` against the production database and bucket, and confirm every row with an `image_key` now has a `cover_key`.
3. Deploy the API and frontend that read `cover_key`. Doing this before step 2 would show every set text-only until the command has run.

**Key interfaces:**
- `ExpansionSet` entity: new `CoverKey`.
- `cmd/presize-images`: reads from and writes to R2 through the same storage adapter the other hosting commands use; the `vips` call sits behind a small function so it can be faked in tests (ADR-0011).
- `catalog_mapper.go` and the `CardResult` repository query: switch the Expansion Set image from `ImageKey` to `CoverKey`.
- `frontend/src/lib/image.ts` and `expansion-set-tile.tsx`.

**Acceptance criteria:**
- [ ] `presize-images` produces, for each Expansion Set with an original, one WebP object no larger than 128px on its longest side, with alpha preserved, and sets `cover_key`; a second run changes nothing; with `vips` missing it exits non-zero with a clear message before touching anything.
- [ ] `GET /catalog/series`, the catalog card search (`CardSummary.expansionSet`) and the expansion set facet options return `imageUrl` built from `cover_key`, and `""` when it is empty.
- [ ] The Expansion Set tile loads the cover directly, not through `/cdn-cgi/image/`; an empty or failing address renders the text-only tile with no layout shift.
- [ ] Card tiles and the card detail view are unchanged.
- [ ] Backend `go build/vet/gofmt/test ./...` clean (including a test for the command with a faked R2 and a faked `vips`); frontend lint/typecheck/test clean; `image.test.ts` and `expansion-set-tile.test.tsx` updated.
- [ ] `images.md` documents the command, the column and the rollout order.

**Out of scope:**
- Series logos, tracked in #15.
- Card images, which stay original-size and read-time.
- Deleting the original objects or the superseded `cdn-cgi` configuration; originals are the re-size source.
- Re-ingesting or re-downloading anything from pokemonasia.
- Changing the 128px size; the maintainer will iterate on it if the covers look soft.

## Comments

Grilling session, 2026-10-05 — arose from #15. The maintainer asked to evaluate pre-sizing Expansion Set covers as well, since no feature shows one at full size, and asked that it be done from the hosted images, not by re-downloading from pokemonasia. Settled: shell out to `vips` (these commands are run by hand, never on Railway), add a separate `cover_key` and leave `image_key` as the original, run as a second idempotent step after ingestion, text-only tile until it has run. Recorded in ADR-0017. A prior estimate showed read-time transformation would cost only about 94 transformations a month against the 5,000 free allowance, so this is not a quota fix; it removes the dependency on Image Transformations and the redirect fallback for covers.
