# 33: Infinite, virtualized catalog search

## Agent Brief

**Category:** enhancement
**Summary:** Replace the numbered pager on the catalog search page with load-more-on-scroll, rendered through a virtualized responsive grid of card tiles.

**Current behavior:**
The catalog search is offset based (`page`, `limit`, `meta.total`) and the frontend shows numbered page controls. There is no infinite scroll and no virtualization.

**Desired behavior:**
- Scrolling near the bottom of the results loads the next page automatically; the user never sees page numbers.
- Data comes from an infinite query over the existing `page`/`limit`/`total` contract (no backend change; the ordering already ends in `cards.id`). Loaded cards are flattened and deduplicated by card id. A non-200 response is an error, not an empty page.
- Results render through TanStack Virtual (add `@tanstack/react-virtual`): a window virtualizer over rows of tiles, with the number of columns derived from the container width (responsive, matching today's breakpoints) and variable row height measured, not assumed. Sticky header and app shell offsets are accounted for.
- "Near the bottom" is detected from the virtualizer's last rendered row versus total rows; the trigger is guarded so it never fires while a fetch is in flight.
- A focusable "Load more" button after the list is both the fallback control and a trigger. It uses `aria-disabled`, not `disabled`, when there is nothing to load. A polite status line reads "N of total cards loaded".
- `page` is removed from the search params and `loaderDeps`; the URL carries filters only. A filter change starts a fresh list from the top. The route loader prefetches page 1 of the infinite query.
- The shared card tile and quantity controls are reused unchanged.

**Key interfaces:**
- The generated API client (enable infinite query generation for the catalog search operation; use the generated infinite key helpers).
- The catalog search route, its search-param schema and loader dependencies, and the shared card results component.
- Keep the grid component generic enough that tickets 35 and 36 can reuse it.

**Acceptance criteria:**
- [ ] Scrolling the catalog search to the bottom loads further pages until `total` is reached, with no duplicate tiles
- [ ] The DOM holds only a window of rows (verify with a seeded list of about 2,000 tiles that scrolling stays smooth and the rendered tile count stays bounded)
- [ ] Columns follow container width and the grid stays correct on resize
- [ ] Changing a filter resets the list to the top and the results match the new filters; the URL contains no `page`
- [ ] The "Load more" button works with the keyboard and loads the next page; the status line is announced politely
- [ ] Unit tests (virtualizer layout needs jsdom stubs; IntersectionObserver stubbed if used) and a Playwright e2e for scroll loading and filter reset
- [ ] Both verification scripts pass

**Out of scope:**
- Accessibility refinements (list semantics, focus retention, column-change re-anchor, scroll restoration): ticket 34
- Expansion Set page, Collection entries, Master Inventory, quantity lookups: tickets 35 to 37
- Cursor pagination, backend changes, changes to the filters themselves
