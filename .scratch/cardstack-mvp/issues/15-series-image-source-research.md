## Agent Brief

**Category:** enhancement
**Summary:** Give each Series an Indonesian-region logo, hosted in our own R2 bucket already resized, and show it in the catalog browse page's Series section heading. Source and rationale are settled in `.scratch/cardstack-mvp/research/series-image-source.md` and ADR-0017; this ticket does not re-open them.

**Current behavior:**
`Series` (`backend/internal/domain/entity/series.go`) has only `Code` and `Name`, so it has no image. The catalog browse page (`frontend/src/routes/catalog/index.tsx`) renders each Series as a text-only `<h2>`. pokemonasia exposes Series only as a free-text label (ADR-0008), so there is nothing to scrape.

**Desired behavior:**
1. A committed shell script builds four finished logo files from the source originals and the files are committed under `backend/assets/series/`: one WebP with alpha per Series, 80px tall, width following the aspect ratio, named by Series code. The script uses `vips`.
2. A new Go command, `cmd/host-series-images` (sibling of `cmd/host-images`), uploads each file to R2 as `series/<code>.<hash8>.webp` (hash of the file content, so the `immutable` one-year cache stays safe if a logo is re-cropped) and stores the key on the matching Series row. It is idempotent: re-running with unchanged files is a no-op; a changed file gets a new key and the row is updated. It uploads with `Content-Type: image/webp` and the same `Cache-Control: public, max-age=31536000, immutable` the other hosting commands use. It needs the same four `R2_*` settings, exits non-zero if a file could not be uploaded or no Series row matched its code, and logs the match count.
3. `Series` gains `ImageKey string`, `gorm:"not null;default:''"`, the same shape as `ExpansionSet.ImageKey`. The ingester's `upsertSeries` must keep leaving it alone (it only writes `Name`).
4. `SeriesSummary` exposes `imageUrl`, built from `ImageKey` through the same `ImageHost.URL` helper the Expansion Set mapper uses, empty when the key is empty.
5. The Series heading shows the logo when `imageUrl` is non-empty. The `<h2>` keeps the Series name as visually hidden text inside it (so the heading, the `aria-labelledby` on the `<section>` and the document outline are unchanged) and the image is decorative (`alt=""`). A Series with no image, or an image that fails to load, renders today's text heading. Reserve the slot with a fixed height so loading does not shift the page. Check the logo on both light and dark themes. The implementation follows the `accessibility` and `frontend-design` skills.
6. Pre-sized URLs must skip the read-time rewrite: do not route the Series logo through `imageSources()` (`frontend/src/lib/image.ts`), which would turn it into a `/cdn-cgi/image/...` transformation address.
7. Rollout order, in the PR description and in `images.md`: apply the migration that adds `series.image_key` with `make job` against production first (additive only, the running API is unaffected), then run `host-series-images`, then deploy the API and frontend that read it. Running the command before the migration writes to a column that does not exist; deploying before the command shows text-only headings until it has run.
8. Update `docs/agents/deployment/images.md` with the new command, the `vips` requirement for the script and the `series/<code>.<hash8>.webp` key scheme.

**Source of the originals** (full URLs, licence and the extraction notes are in the research note):
- Scarlet & Violet: `SV Era Logo I.png` (Bulbagarden Archives).
- Sword & Shield: `Sword Shield Logo Indonesian.png`.
- Mega Evolution: `Mega Evolution Logo Indonesian.png`.
- Sun & Moon: `First_Impact_Logo_Indonesian.png`, a set logo with the Series wordmark on top and the set name underneath. Crop to rows 0-182 of the 1177x298 original (a fully transparent band at rows 182-188 separates the two), then resize like the others.

**Series codes:** `slugifySeries` (`backend/internal/adapters/ingestion/pokemonasia/mapper.go`) builds them from the ingested display name. `scarlet-violet` and `evolusi-mega` are asserted in `mapper_test.go`; `pedang-perisai` and `matahari-bulan` follow from the same function applied to the glossary names "Pedang & Perisai" and "Matahari & Bulan" but are not asserted anywhere. Confirm all four against the real rows before naming files, since a wrong code silently matches zero rows.

**Key interfaces:**
- `Series` entity: new `ImageKey`.
- `ToSeriesSummary` (`backend/internal/domain/mapper/catalog_mapper.go`) takes the `ImageHost` the other mappers take, and `SeriesSummary` (`catalog_dto.go`) gains `ImageURL string json:"imageUrl"`. Regenerate the frontend client (orval) after the DTO changes.
- New `cmd/host-series-images` plus a Makefile target mirroring `make host-images`.
- The Series heading in `frontend/src/routes/catalog/index.tsx`, possibly extracted into a small component.

**Acceptance criteria:**
- [ ] The script regenerates the four committed WebP files from the originals, and the Sun & Moon file shows only the "MATAHARI&BULAN" wordmark, no set name.
- [ ] `cmd/host-series-images` uploads four objects named `series/<code>.<hash8>.webp` and sets `series.image_key` on four rows; a second run changes nothing; editing a file produces a new key.
- [ ] `GET /catalog/series` returns a populated `imageUrl` for each Series that has a key, and `""` for one that has none.
- [ ] The catalog browse page shows the logo in each Series heading; the heading's accessible name is still the Series name; a Series without an image renders the plain text heading; there is no layout shift and no broken-image icon.
- [ ] The logo is requested directly, not through `/cdn-cgi/image/`.
- [ ] Backend `go build/vet/gofmt/test ./...` clean; frontend lint/typecheck/test clean; new unit tests cover the mapper and the heading with and without an image.

**Out of scope:**
- Expansion Set covers, tracked in #38.
- Any in-app attribution for the artwork; none is added, the same as the pokemonasia-sourced card and set art (ADR-0017).
- Scraping or fetching Series images during ingestion.
- A fallback to the Bulbagarden address when `image_key` is empty.
