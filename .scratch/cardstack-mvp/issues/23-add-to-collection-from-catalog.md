# 23: Add cards to a Collection from the catalog page (authenticated users)

**Category:** enhancement
**Status:** done — implemented (frontend `8aa4a57` + `c4ab905`), merged to `main`.

**Blocked by:** 20 (Inventory bulk update endpoint), 22 (Collection detail page on the shared catalog layout)

## Agent Brief

**Category:** enhancement
**Summary:** On the public catalog page, a logged-in user picks one of their Collections and edits how many of each card it holds using the same quantity control as the Collection detail page. Guests see the control disabled.

**Current behavior:**
The catalog is a public read-only view. The only way to add a Card to a Collection is the name-search picker on the Collection detail page.

**Desired behavior:**
- The catalog search page shows an "Add to collection" selector listing the user's Collections. It is enabled only for an authenticated user. For a guest it is shown disabled with a prompt to log in, and the page stays fully usable for browsing. Authentication state is determined without redirecting (the catalog stays public).
- Once a Collection is selected, every card tile on the page shows the shared quantity control from ticket 22 with that Collection's current quantity for the card (0 when it is not in the Collection). Editing it uses the same debounced batching, ordering, capacity-decline handling and bulk endpoint as the Collection detail page, so a card can be added by increasing from 0.
- The selected Collection is kept in the URL search params or equivalent so a reload keeps it. If the Collection no longer exists or the user logs out, the selection clears.
- Quantities shown come from the selected Collection's contents for the cards on the current page (for example by fetching the Collection's entries for those card ids), and update when the user edits.
- The now-redundant name-search picker on the Collection detail page is removed.

**Key interfaces:**
- The shared card tile's per-card control slot from ticket 22, filled with the quantity control when a Collection is selected.
- A client-side authentication probe usable on a public route, without the redirecting route guard.
- The Collection entries lookup used to fetch quantities for a set of card ids on the current catalog page; add a backend parameter if the existing filtered entries endpoint cannot do this efficiently.

**Acceptance criteria:**
- [ ] A guest sees the selector disabled with a login prompt and no quantity controls, and browsing and filtering still work
- [ ] An authenticated user can select one of their Collections and see per-card quantities for it on catalog results
- [ ] Increasing a card from 0 adds it to the Collection, verified by the Collection detail page
- [ ] Capacity-declined additions revert with an error message, same as ticket 22
- [ ] The selected Collection survives a reload and clears when it is invalid or the user is logged out
- [ ] The picker on the Collection detail page is removed
- [ ] Frontend tests cover guest, authenticated and decline cases, and an e2e spec covers the authenticated add flow if the environment can run it; both verification scripts pass

**Out of scope:**
- Restricting which catalog filters guests may use (ticket 24)
- Master Inventory or cross-Collection lookup
- Creating a Collection from the catalog page
