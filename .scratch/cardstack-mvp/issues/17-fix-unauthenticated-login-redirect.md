# 17: Fix post-login redirect when navigating to protected routes while unauthenticated

## Agent Brief

**Category:** bug
**Summary:** When navigating to a protected route (such as `/collections`) while unauthenticated, the user is redirected to `/login?redirect=...`. However, after successfully logging in, the app fails to redirect the user to their original attempted destination and instead defaults to `/account`.

**Current behavior:**
- `requireAuth` in `frontend/src/lib/route-guard.ts` throws a router redirect to `/login` with `search: { redirect: location.href }`.
- In TanStack Router runtime, `location.href` may resolve to an absolute URL string (e.g. `http://localhost:3000/collections`).
- `loginSearchSchema` in `frontend/src/routes/login.tsx` validates the `redirect` search parameter with `.refine((path) => path.startsWith("/") && !path.startsWith("//"))`. Absolute URLs fail this check, causing `redirect` to be cleared/undefined.
- Upon successful login, `LoginPage` in `frontend/src/routes/login.tsx` attempts `navigate({ to: isSameOriginPath ? redirect : "/account" })`, which falls back to `/account` whenever `redirect` is omitted or invalid.

**Desired behavior:**
1. Update `requireAuth` in `frontend/src/lib/route-guard.ts` to pass a relative path (`location.pathname + location.searchStr`) instead of `location.href`.
2. Ensure `LoginPage` in `frontend/src/routes/login.tsx` correctly handles relative post-login redirect targets (such as `/collections`) and navigates to the attempted URL.
3. Add unit test coverage in `frontend/src/lib/route-guard.test.ts` (and/or `frontend/src/routes/login.test.tsx`) verifying that `requireAuth` preserves path + search strings and that login navigation respects the `redirect` parameter.
4. Add Playwright e2e test coverage in `frontend/e2e/auth-redirect.spec.ts` (or similar) verifying that unauthenticated navigation to `/collections` redirects to `/login?redirect=...`, and completing login redirects the user back to `/collections`.

**Acceptance criteria:**
- [ ] Navigating to `/collections` while unauthenticated redirects to `/login` with a valid same-origin relative `redirect` query parameter.
- [ ] Submitting valid login credentials on `/login?redirect=/collections` redirects the user to `/collections`.
- [ ] Unit tests in `frontend/src/lib/route-guard.test.ts` cover relative path and search parameter preservation.
- [ ] Playwright e2e test covers unauthenticated navigation to protected routes and post-login redirect flow.
- [ ] All frontend unit tests (`bun run test`), linter (`bun run lint`), and typecheck (`bun run typecheck`) pass cleanly.
