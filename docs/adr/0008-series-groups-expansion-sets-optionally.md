# Series is a first-class, optional grouping above Expansion Set

The replacement ingestion source (`asia.pokemon-card.com`) groups Indonesian Pokémon Expansion Sets under four named product lines (Scarlet & Violet, Sword & Shield, Sun & Moon, Mega Evolution) — a real domain concept the old TCGDex integration also touched (its `GET /{locale}/series/sv` endpoint) but never persisted, only used transiently to enumerate sets during ingestion. We modeled it as its own `Series` entity with a nullable FK on `Expansion Set`, rather than a plain string column, because it's a genuine recurring identity (own attributes like release-date range or ordering may follow) and because the concept generalizes as a *mechanism* — an optional grouping layer between Game and Expansion Set — even though not every Game will have one (a brand-new Game with few sets released so far, e.g. Riftbound, may have zero Series for a while; that's a valid state, not a gap to fix).

Confirmed via direct inspection of the source's HTML/JS (`#productSelectorModal`, `/build/app.js`): the site exposes Series only as a free-text display label ("Evolusi Mega"), with no accompanying code anywhere in the markup, JS, or query params — only the individual Expansion Sets nested under it carry a machine-readable value (`class="expansionCode" value="MA6"`). `Series.code` is therefore locally derived (e.g. slugified from the name) rather than source-provided, unlike `Expansion Set.code`, which is the source's own value. Worth knowing before someone assumes both codes come from the same place.
