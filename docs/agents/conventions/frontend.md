# Frontend code conventions

These apply to every frontend change, whether made by the root agent or a subagent. Read `general.md` in this folder as well.

- Extract a component once reuse is real, not in anticipation of it.
- Treat everything in the client bundle as public: render no unsanitized HTML and ship no secrets.
- When you couldn't verify a UI change in a browser, say so instead of claiming success.
- Treat `src/generated/**` (orval) and `src/routeTree.gen.ts` as build outputs. Change the source (the OpenAPI spec, the route files) and regenerate: `bun run codegen` for orval, and the TanStack Start Vite plugin rebuilds the route tree.
- Colocate unit tests beside the source as `*.test.ts(x)`. End-to-end Playwright tests live in `e2e/`.
- `.oxlintrc.json` is the source of truth for lint rules, including the `anti-slop/*` set. `bun run lint` must pass.
- Format proactively: run `bun run format` after editing so `bun run check` (Prettier) passes. `tools/oxlint/anti-slop` comes from an externally installed plugin, so it stays in `.prettierignore` and is never reformatted by hand.
- On public routes, read auth state with `useSession()` (no redirect) and gate features on `isAuthenticated`; only `requireAuth` under `_authenticated/` redirects.
- Quantity editing goes through `useQuantityBatch` + `QuantityControl`; new surfaces reuse them rather than re-implementing batching, ordering or decline handling.
- The `cardId` entries filter treats an empty list as "no restriction": disable the query when there are no ids rather than sending an empty list.
- Debounce with TanStack Pacer's `useDebouncer` (`@tanstack/react-pacer`), not hand-rolled `setTimeout`/`clearTimeout` timers; pass `onUnmount: (d) => d.flush()` when pending work must survive unmount, and call the latest handler through a ref to avoid stale closures.
- Multi-value filter dropdowns use `MultiSelect` (`components/ui/multi-select.tsx`, a base-ui Popover of native checkboxes); the popover only mounts when open, so tests and e2e must click the trigger first. Render active-selection chips as buttons, not `li`, because e2e specs count results by `listitem`.
- Read and set the theme through `ThemeProvider` / `useTheme` (`components/theme-provider.tsx`); don't touch the `dark` class or `localStorage` directly.
- Header and footer nav links come from `useNavLinks` (`components/layout/nav-links.ts`); add new top-level destinations there. Keep nav as plain links in a `nav`, with no list markup, because e2e specs count `listitem`.
- Pages must not render their own `<main>`: each shell (`AppShell`, and `AuthShell` under `routes/auth/`) owns its single `main` landmark, so use a `<div>`.
- Use `text-muted-foreground` only where contrast is verified; axe flags low-contrast shell text.
- Lay out every page with `PageContainer` and `PageHeader` (`components/layout/`); pages never render their own wrapper `div`, `main` or `h1`. `PageContainer` variants: `narrow` for auth pages, `default` for everything else, `wide` only for catalog search and Master Inventory. `PageHeader` renders the page's single `h1`, with an optional `description` and `actions` slot.
- Nested pages show `Breadcrumbs` (`components/layout/breadcrumbs.tsx`) above the header: ancestors are links, the last crumb is the current page. Top-level pages (Catalog, Collections, Master Inventory, Account) have none, and no page renders a "Back to ..." link. Breadcrumbs are plain links in a `nav`, with no list markup, because e2e specs count `listitem`.
- `/` renders `HomePage` (`components/home/`): a skeleton while `useSession()` is loading (never marketing copy), then the signed-in `Dashboard` or the `GuestLanding`. A failed or 401 session check is a guest. Keep any new `/` content behind that switch so a signed-in user never sees the landing flash.
- The dashboard shows only what the API returns today: no total owned quantity (the API has no such field). Its "distinct cards" figure is the Master Inventory list's `meta.total` (the backend groups by card and sums quantity, so it counts distinct Cards, not entries), requested with `limit: 1`.
- The Account page is settings-style (profile and session sections); it carries no navigation links, since the header and user menu own navigation.
- Static prerendering of the landing is not used. TanStack Start's top-level `prerender` option can be combined with `spa: { enabled: true }` (SPA mode already prerenders the root route to `_shell.html`, with no route content), but the session lives in HttpOnly cookies the server can't read, so a prerendered `/` would have to pick either the landing (flashing marketing copy at signed-in users) or the skeleton (no better for crawlers than the shell). Crawlers that run scripts get the guest landing from the SPA. Revisit only if the home page stops depending on the session.
- Playwright stubs of paginated API lists (`inventory/cards`) must include `meta: { total, page, limit }`, since the dashboard reads `meta.total`. Echo the request's `origin` header in stubbed CORS responses instead of hard-coding a port.
- Everything under `routes/auth/` (`/auth/login`, `/auth/register`, and anything added later) is guest-only and has its own shell: the layout route `routes/auth/route.tsx` holds `beforeLoad: requireGuest` (pages don't repeat it) and renders `AuthShell` (`components/auth/auth-shell.tsx`: wordmark, theme toggle, the single `main`, no site header or footer). `__root.tsx` skips `AppShell` when the `/auth` route is matched, so don't wrap auth pages in it. Unknown `/auth/*` paths and bare `/auth` render the not-found view inside `AuthShell` (layout `notFoundComponent`, plus `auth/index.tsx` for bare `/auth`). Test the layout's guard and shell in `routes/auth/-route.test.tsx`, not per page.
- Login and register render through `AuthPage` and `AuthField` (`components/auth/`): field errors are inline and tied to their input (`aria-describedby`, `aria-invalid`, a `role="alert"` message), form-level server errors stay inline too, and a `type="password"` `AuthField` carries the show/hide toggle. No toasts on auth forms.
- `requireAuth` passes the attempted `pathname + searchStr` (never `location.href`, which can be absolute) as `/auth/login`'s `redirect` param. Every redirect target must pass `isSameOriginPath` (`lib/route-guard.ts`), and is followed with `router.history.push`, since `navigate({ to })` doesn't take a query string. `requireGuest` fails open so a guest is never locked out of the forms.
- Mutations that change the session return `resetCache(...)` from `onSuccess` so the session query has refetched before the caller redirects; otherwise a guard on the next route reads the stale cached 401 and bounces back to login.
- Test files under `src/routes/` must be named `-<name>.test.tsx`: the router plugin treats the `-` prefix as "not a route" and warns on any other file that doesn't export a `Route`.
- Don't use `text-primary` (amber) for text on light surfaces: it fails contrast. Use `text-foreground` with an underline for inline links.
- Every Inventory Entry change must call `invalidateCollectionCounts(queryClient, collectionId)` (`lib/collections.ts`) next to `invalidateMasterInventory`, because a Collection's `cardCount` is derived from its entries and the Collections list loader serves cached data (`ensureQueryData`). It refetches with `refetchType: "all"` so an inactive cached list doesn't flash the old count on the next visit.
- Prefer a whole clickable surface over a small text link: a card that represents an entity navigates to it from anywhere on the card, not only from its title. Use the stretched-link pattern: the title is a single `Link` whose `after:absolute after:inset-0` pseudo-element covers the `relative` card, so the card is keyboard-focusable, activates on Enter and has one accessible name. Secondary actions (edit, delete) sit above it with `relative z-10`, so they stay independently clickable and never trigger navigation. Don't nest interactive elements inside the link or wrap the whole card in an anchor.
- Feedback channel: failures of non-form actions (logout, and any future shell-level action) show a toast via `toast.error(...)` from `sonner`; the single `Toaster` (`components/ui/sonner.tsx`, themed through `ThemeProvider`) is mounted in `__root.tsx`. Form validation, dialog errors, per-card quantity edits and failed page data stay inline (`role="alert"`), and failed page data should offer a Retry action. Don't migrate per-feature mutations to toasts. Mutations resolve for every HTTP status, so a toast needs both the non-success `status` branch in `onSuccess` and `onError`.
- Not-found and crash views: the router's `defaultErrorComponent` is `CrashFallback` (a friendly message plus Reload; it never reads or renders the error), and the root `notFoundComponent` is `NotFound` (Home and Catalog links). To make a missing entity show "<Resource> not found" instead of a generic page, have the route's `loader` check the response and `throw notFoundResource("Collection" | "Card")` (`components/layout/not-found.tsx`); both views render inside whichever shell the route lives in. A crash in the shell itself (outside any route) is caught by the root boundary and replaces the shell with the same fallback; that case is accepted and not tested.
- Every route sets its document title with `head: () => pageHead("<Name>")` (`lib/site.ts`, rendered as "<Name> · Cardstack"); detail routes return the entity name from their `loader` and use `loaderData` in `head`, falling back to a generic name. Only the root sets Open Graph tags: they are static because link-preview crawlers don't run scripts, and `og:image` (`public/og-image.png`) is skipped when `VITE_SITE_URL` is unset.
- Indexing: the `_authenticated` and `auth` layout routes add `NOINDEX_META` in their `head`, so new routes under them are covered; public routes add nothing. That `<meta>` only exists once scripts run, so `vercel.json` also sends `X-Robots-Tag: noindex` for `/auth/:path*` (the one server-visible directive; authenticated paths rely on the robots.txt disallow instead). `public/robots.txt` disallows authenticated paths but deliberately not `/auth`, so the noindex tag stays readable. The build (`bun tools/seo-files.ts`, part of `bun run build`) writes `sitemap.xml` and the robots `Sitemap:` line from `VITE_SITE_URL`, and skips both with a warning when it is unset, so set it in the production Vercel environment. The sitemap lists `/` and `/catalog` only and assumes the Catalog stays public; if guest catalog locking (ticket 24) changes that, edit `PUBLIC_PATHS` in `tools/seo-files.ts` and `public/robots.txt`.
- Titles and noindex come from the client router: SPA mode prerenders only a root shell, built by crawling `/`, so its title is the landing's and non-script crawlers see that title (and no noindex) on every URL. Playwright checks of a layout's child routes should reach them by client navigation, because the dev server renders a direct load on the server, where browser-level API stubs don't apply.
- The catalog search is an infinite query (`useInfiniteCatalogCards`, `lib/infinite-catalog-cards.ts`) rendered by `InfiniteCardResults` over the generic `VirtualGrid` (`components/catalog/`). The URL carries filters only (no `page`), the query key is the filters, and a filter change starts a fresh list from the top. Reuse these for other long lists, with `prefetchInfiniteCatalogCards` in the route loader (only where the list should be warm on arrival: the Collection and Master Inventory routes skip it, since both refetch on mount) and `useInfiniteCardResultsProps(query)` to feed `InfiniteCardResults` (it owns the `cancelRefetch: false` load-more wrapper, so don't re-implement it per route); the Expansion Set page, the Collection detail entries and the Master Inventory already use them (none keeps a `page` in the URL: their schemas are `catalogFilterSchema`, so a stale `?page=` is ignored), and the numbered `CardResults` pager is deleted. The page plumbing shared by every scrolling list (`nextPageParam`, `mergePages`, `infinitePages`: throw on non-200, dedupe by id, `getNextPageParam`) lives in `lib/infinite-pages.ts`; add a list by calling those, not by copying the catalog hook. `CollectionCardResults` looks up quantities with one `useQueries` query per slice of loaded cards (slice size `CATALOG_PAGE_SIZE`, under the batch endpoint's `limit` cap of 100), so appending a page adds a lookup instead of changing the key of the earlier ones, and a tile shows its control once its own slice has loaded. A save refreshes only the lookups that asked for the saved cards (`invalidateCollectionEntries(queryClient, collectionId, cardIds)`); with no card ids (a lost response) it refreshes them all.
- Virtualized lists render only a window of `listitem`s, so Playwright checks on long lists must assert through the status line ("N of total cards loaded") or a request log, not `listitem` counts. Unit tests of virtualized components call `stubGridLayout()` (`src/test-grid-layout.ts`), because the virtualizer measures rows by `offsetHeight` and `test-setup.ts` stubs `ResizeObserver`.
- orval `override.operations` keys are the spec's operationIds (`"search-catalog-cards"`), not the generated function names; a wrong key silently generates nothing. Infinite query keys start with `'infinite'`, so invalidating by the plain query-key helper misses them: use the generated infinite key helper. The plain list hooks stay generated beside the infinite ones and some surfaces still use them (the dashboard's `limit: 1` Master Inventory count, the catalog's quantities lookup), so an invalidation that must reach a list invalidates both key roots: call `invalidateMasterInventory` (infinite list, plain list, facets) and `invalidateCollectionEntries` (`lib/collections.ts`: infinite list and plain lookups) and never the bare key helpers for an invalidation (a cache patch targets the infinite key on purpose). Test an invalidation with real keys in a real `QueryClient` (`isInvalidated`), as `master-inventory.test.ts` and `collections.test.tsx` do, because a mocked `invalidateQueries` can't notice a prefix that misses.
- `VirtualGrid` markup is `role="list"` > presentational row wrappers > `role="listitem"` tiles with `aria-posinset` and `aria-setsize`. Pass `totalCount` (the server total) so the set size is the whole result set, not the loaded part. Don't put row wrappers inside a `ul` (invalid HTML, and axe flags it).
- The grid keeps the row holding focus rendered (a custom `rangeExtractor`), and pauses scroll-triggered loading while a tile has `:focus-visible` focus, so keyboard users aren't moved by new rows. "Load more" is their path while more pages remain (Tab goes last tile, Load more, footer); once the last page is loaded the button is removed and Tab goes straight to the footer. Known limitation: a column change (resize across a breakpoint) remounts every tile, so a focused tile loses focus.
- `scrollPaddingStart` (`HEADER_HEIGHT` in `virtual-grid.tsx`) must match the sticky header's `h-14` (56 px). When the column count changes the grid re-anchors the card at the top of the viewport one animation frame later (a synchronous re-anchor lands about 15 rows off).
- Programmatic scrolls (re-anchor, filter reset, router scroll restoration via `scrollRestorationBehavior: "instant"` in `router.tsx`) are always instant, which is how reduced motion is respected. Don't add CSS `scroll-behavior: smooth`.
- Browser find-in-page (Ctrl+F) only sees rendered rows. This is a known limitation of virtualizing; don't work around it.
- `stubGridLayout()` also stubs `scrollY`, `scrollHeight` and `scrollTo`, and offers `scrollTo(top)` and `resize(width)`. Virtual-core skips synchronous measurement during user scroll and relies on `ResizeObserver`, which the stub never fires. `scrollToIndex` reschedules its own animation frames, so queue frames and run them one at a time instead of running `requestAnimationFrame` inline.
- Playwright on virtualized lists: click an in-viewport link when asserting scroll restoration (Playwright scrolls the target into view first), `locator.focus()` is not necessarily `:focus-visible`, and to test reaching the end of a list by keyboard, load every page first.
- The Collection entries (`useInfiniteCollectionEntries`) and Master Inventory (`useInfiniteMasterInventory`) hooks live in `lib/infinite-inventory.ts`, page size 100. Collection entries keep `gcTime: 0` + `refetchOnMount: "always"` (a card taken to 0 must not reappear from cache, so back navigation lands at the top) and `refetchOnWindowFocus: () => !batch.isBusy()`. Both lists use `placeholderData: keepPreviousData`, so on a filter change the old tiles stay (and stay editable) until the first page of the new filters lands. Master Inventory is read-only, so it keeps the default `gcTime` (back navigation restores the scroll position from cached pages) with `refetchOnMount: "always"` and `staleTime: 60_000`.
- A `select` result must be a plain object or array, never a `Map` or `Set`: structural sharing only preserves identity for plain values, and an effect keyed on `query.data` (the `prune` effect) loops forever on a fresh `Map` each render. `InventoryList.quantities` is a `Record`.
- After a quantity save the cache is the source of truth: `onSaved(results)` receives the bulk response's per-card results (empty if the response was lost) and `CollectionEntries` calls `patchCollectionEntryQuantities` (`lib/collections.ts`) instead of refetching. A refetch costs a request per loaded page and drops a card saved at 0, whose tile must stay. `onSaved` may return a promise, and the batch stays busy until it settles, so the patch lands before cards lose protection. The patch first cancels in-flight fetches of queries that already hold pages (a page append writes back the pages it saw when it started, undoing the patch; the grid asks for the cancelled page again; a first fetch is never cancelled, since nothing would restart it), writes into every cached page, keeps `{ pages, pageParams }`, and preserves the identity of untouched pages. New surfaces that render a quantity from a cached infinite list do the same; a plain lookup query (the catalog's quantities lookup) is invalidated and refetched instead. A lost response (empty results) has nothing to patch from, so `CollectionEntries` invalidates the entries list then. `onSaved` runs inside a guard in `useQuantityBatch`: a throw there can't revert a saved card or stall the queue.
- `prune(serverQuantity)` drops an override or error only when the server data now differs from what the hook last confirmed for that card (or the row is gone: the callback returns `undefined`; a caller whose lookup only covers some cards returns `undefined` for the rest and `0` for a covered card missing from the result), so appending a page or patching the cache never reverts a saved value or wipes a declined card's error. Pass it the list's current server quantity per card.
- Known and accepted: when a card is saved at 0 and a later page then loads, the server list is one row shorter than the client list, so the first card of that page is skipped until the next real refetch (focus, remount, any invalidation).
- Fake network functions in component tests of infinite lists must take a tick (`await new Promise((r) => setTimeout(r, 1))`): the grid asks for the next page only after it renders a fetch as in flight, which an instantly resolved fake never does. Playwright against the dev server can see a page requested twice (StrictMode remount), so assert the set of requested pages, not their counts.
