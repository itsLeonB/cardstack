# Backend code conventions

These apply to every backend change, whether made by the root agent or a subagent. Read `general.md` in this folder as well.

## Errors

- Wrap with `ungerr.Wrap`/`ungerr.Wrapf` at the exact first location an error originates in our own code (e.g. inside the helper that calls `rand.Read`). Callers of our own functions, and of `crud.Repository` (it already wraps with ungerr), return the plain `err` unchanged. The single Huma-level seam (`backend/internal/adapters/http/huma/errors.go`, ADR-0013) classifies and unwraps it once.
- Return known, client-safe failures as `ungerr.XxxError(...)` AppErrors. Handlers return AppError types rather than calling `huma.ErrorXXX(...)` with ad hoc messages (ADR-0013).
- Construct each `ungerr.XxxError(...)` at its return site, because ungerr records the line that built it. Share only the message as a constant.
- Handle every error. Log a non-blocking one with `logger.Error`/`logger.Errorf` (`backend/internal/core/logger`, whose `Global` is a safe no-op until `Init` runs) and carry on; return the rest. Never discard with `_ =`.

## Layout

- Put a Service in `internal/domain/service/<name>_service.go`, interface and implementation in that one file. Give an entity its own Repository (`internal/domain/repository/<name>_repository.go`, same one-file shape) only when it needs custom GORM calls or raw SQL; otherwise the service holds a plain `crud.Repository[entity.X]`. Reserve `internal/adapters/` for modules with a real second implementation. Read `docs/adr/0011-domain-owns-business-logic-and-data-access-adapters-are-for-interchangeable-infrastructure.md` before placing a new Service or Repository.
- When a custom repository is needed but plain `crud.Repository` covers most operations, embed `crud.Repository[T]` in the custom repository's struct and take it as the constructor argument (`NewXRepository(base crud.Repository[T])`), instead of injecting `*gorm.DB`. Custom methods get the database from `GetGormInstance(ctx)`, which returns the transaction carried by a ctx from `Transactor.WithinTransaction` and otherwise `db.WithContext(ctx)`. Example: `InventoryRepository` embeds the base repository and adds only `SumQuantity`, because go-crud has no aggregate. Never hold a bare `*gorm.DB` or call `db.WithContext(ctx)` in a repository, not even for plain reads: it ignores the transaction carried by ctx. A repository with no natural entity (`CatalogRepository`) still embeds a `crud.Repository` of any entity purely for `GetGormInstance`.
- Name lookups by what they promise. A `find*` method may return a nil or zero result without an error, so the caller must check it itself (go-crud's `FindFirst`/`FindAll` are the model). A `get*` method guarantees the result exists and returns an error (usually the not-found AppError) otherwise, so the caller can use the value directly. Repository methods that every operation starts with, such as an owner-scoped lookup, belong on the repository as `get*` (`CollectionRepository.GetOwnedCollection`), not as a private helper in a service. A name fixed by an external interface (go-authkit's `FindByID`, `FindByEmail`) is exempt.
- Give every service method the signature `(ctx, dto)` at most: put the session `profileID`, path ids and body fields together in one request DTO (`internal/domain/dto`), never in loose parameters. The handler builds that DTO from the Huma input type (which stays separate from the DTO) plus the profile ID from the session. A method with nothing to pass takes only `ctx`. Use a small dedicated DTO for lookups and lists (`CollectionLookup`, `CollectionListRequest`) rather than bare ids.
- Never share logic between services through a package-level function that takes a dependency (a repository, another service) as a parameter. Either extract it into its own service struct, or let one service own it and have the other depend on that service. A pure function with no dependencies may be shared at package level (`normalizePagination`, `pagedRepoFilter`). Pure conversions between types belong in `internal/domain/mapper`, not the service file (`mapper.ToRepoCardFilter`, `mapper.ToCatalogFacets`).
- Put DTOs in `internal/domain/dto` and entity-to-DTO conversions in `internal/domain/mapper` (ADR-0012).

## Data and mapping

- Key domain ownership by `profile_id` (`user_profiles.id`); `user_id` identifies the authentication account only.
- Before making a value optional, ask whether `0` means something different from absent. When both behave the same (a card limit where 0 and none both mean unlimited), use a `NOT NULL DEFAULT 0` column and a plain value, which removes the `> 0` checks. Use a nullable column or pointer only when absent must stay distinguishable from `0`.
- Scope a query in the query itself with `crud.Specification`, never by fetching rows and filtering in Go.
- Map slices with `ezutil.MapSlice`, or `ezutil.MapSliceWithErr` when the mapper can fail.
- Prefer go-crud's own interfaces over custom SQL or joins. Load related rows by declaring the relation on the entity (a field with a `foreignKey` tag) and setting `crud.Specification.PreloadRelations` (nested names work, e.g. `"Card.Rarity"`), not by hand-written joins. Read many rows with `Repository.FindAll(ctx, spec)`, one with `FindFirst(ctx, spec)`, and write with `Insert`, `Update` and `Delete`. `FindFirst` returns the zero value and a nil error on a miss, so test `IsZero()` and map it to not-found. `Specification.Model` drops zero-valued fields from the query, so guard a `uuid.Nil` id or owner before querying and return not-found, or the scoping silently disappears. Put the guard in the method that builds the spec: the repository's `get*` method (e.g. `GetOwnedCollection`) when one exists, otherwise the service.
- Write with check-then-act inside `crud.Transactor.WithinTransaction(ctx, func(ctx context.Context) error)`, passing the callback's `ctx` to every repository call so they join the transaction. Fetch the row with `FindFirst` and `Specification.ForUpdate: true`, check the rule (existence, ownership, capacity), set the new value on the entity struct, then pass it to `Update`. Never infer the outcome from `RowsAffected`. Locking the owning row (the Collection) before checking a limit against current data serializes concurrent writers, so a unique-violation race cannot reach the insert.

## Testing

- Mock any dependency you'd rather not stand up (a repository, a service behind a handler): add the interface to `.mockery.yaml`, run `make mocks`, and use the generated mock, never a hand-written stub or fake. Mocks land in the single committed `internal/mocks` directory (ADR-0012). Handler tests show the pattern with `mocks.NewMockCatalogService(t)` in `internal/adapters/http/handler/catalog_handler_test.go`.
- Run repository-layer tests (`internal/domain/repository`) and feature tests against a real Postgres, because a mock of the DB/GORM layer would reimplement SQL behavior and drift from it (ADR-0005). Tests that merely sit downstream of a repository mock it instead.
- Have a service in `internal/domain/service` depend on its repository through the single exported interface defined beside the concrete implementation (`repository.CatalogRepository` in `internal/domain/repository/catalog_repository.go`), not an interface narrowed to that one service. Its unit tests mock that interface: see `internal/domain/service/catalog_service_test.go` (`mocks.NewMockCatalogRepository(t)`, `.EXPECT().Method(args).Return(...)`).
- Assert with `github.com/stretchr/testify/assert` (`require` when the test cannot continue), not hand-rolled `if ... t.Fatalf`.
- Unit-test a service that holds a plain `crud.Repository[entity.X]` with the generated generic mock `mocks.NewMockRepository[entity.X](t)` (go-crud's `Repository` entry in `.mockery.yaml`). Assert the exact `crud.Specification` passed, since the query carries the scoping.
- Environment setup for tests (Postgres, seed data) lives in `docs/agents/testing.md`.
