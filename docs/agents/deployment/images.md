# Image hosting

Card images, Expansion Set covers and Series logos live in a Cloudflare R2 bucket and are served from our own image host (ADR-0016). Three sides read separate settings:

- API (Railway): `IMAGE_BASE_URL`, the public address of the image host with no trailing path (for example `https://img.example.com`). The API serves `IMAGE_BASE_URL` plus a row's hosted key as its image address. With it unset, or on a row with no key, the address is empty. It never falls back to the scraped source address.
- Frontend (Vercel): `VITE_IMAGE_HOST`, the same origin as `IMAGE_BASE_URL`. The frontend rewrites image addresses on that origin to Cloudflare Image Transformations (`/cdn-cgi/image/width=<w>,format=auto,onerror=redirect/<key>`): card tiles at 240 and 480 wide and the card detail view at 720. Expansion Set covers are not rewritten: they are pre-sized at host time (below) and used as-is. `onerror=redirect` serves the original when the free transformation allowance is spent. With it unset, or on an address from any other host, the address is used unchanged, so local development needs nothing. It is baked in at build time, and Image Transformations must be enabled on the image host's zone (ticket 02).
- Ingester (`go run ./cmd/ingest-pokemon-asia`, run by hand, never on Railway): `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_BUCKET` from an R2 API token scoped to that bucket. `R2_ENDPOINT` is optional and replaces the address derived from the account id. Unless all four of the first group are set, the ingester logs a warning and hosts nothing, so a local ingest of one small set needs no credentials.

Card and Expansion Set keys are `cards/<card id>` and `expansion-sets/<expansion set id>`, so re-running either command is the backfill: it copies only rows whose key is empty, and a failed download or upload is logged and retried by the next run. To migrate rows that are already in the database without crawling the source site at all, run `make host-images` (`go run ./cmd/host-images`, optionally with `-set <code>`): it reads every Expansion Set and card with a source address and no key, downloads each image under the same rules as the ingester, uploads it to R2, and saves the key. It needs the four `R2_*` settings and exits 1 if any image failed, so re-run it to retry just those. The ingester still hosts images for the rows it ingests, and `go run ./cmd/ingest-pokemon-asia -sync-expansion-sets` hosts Expansion Set covers without crawling any card. Hosted originals are uploaded with `Cache-Control: public, max-age=31536000, immutable`, which is safe because a key always maps to the same bytes.

Series logos are hosted separately, because the four Series have no scrapeable image (ADR-0017). `backend/scripts/build-series-logos.sh` downloads the four source originals and writes the finished files to `backend/assets/series/<series code>.webp` (WebP with alpha, 120px tall; Sun & Moon and Scarlet & Violet are cropped first). It needs `curl` and `vips` (`apt install libvips-tools`, `brew install vips`) and is only re-run when a logo changes; the output files are committed. `make host-series-images` (`go run ./cmd/host-series-images`, run from `backend/`, with `-dir` defaulting to `assets/series`) uploads each file to R2 as `series/<series code>.<hash8>.webp`, where `<hash8>` is the first 8 hex characters of the file's SHA-256, and saves the key on the matching Series row. A changed file gets a new key, so the `immutable` cache stays safe, and a second run with unchanged files uploads and updates nothing. It needs the four `R2_*` settings and exits 1 if an upload or save failed, a file's code matched no Series row, or the directory has no files. The API serves the logo address like any other hosted key, and the frontend uses it as-is: the logo is already sized, so it is not routed through the `/cdn-cgi/image/` rewrite above.

Rollout order for Series logos: apply the migration that adds `series.image_key` with `make job` against production first (additive, so the running API is unaffected), then run `make host-series-images`, then deploy the API and frontend that read it. Running the command before the migration writes to a column that does not exist. Deploying before the command shows text-only Series headings until it has run.

Rollout order matters for card and Expansion Set images, because nothing enforces it. `preserve()` in `railway.ts` keeps an existing `IMAGE_BASE_URL` but never creates one, so set it in Railway first. `make host-images` reads the columns the hosted-images migration adds, so apply the migration before running it: run `make job` against the production database, then `make host-images`, and deploy the API right after the migration. That migration drops `image_url` in the same step, so replicas still running the old API fail on catalog queries from the moment it runs until the new API is live. Until `host-images` has hosted a row, that row's image address is empty and the frontend shows its placeholder.

Expansion Set covers are pre-sized once, not transformed at read time (ADR-0017). `make presize-images` (`go run ./cmd/presize-images`, optionally with `-set <code>`) finds every Expansion Set with an `image_key` and an empty `cover_key`, reads the hosted original from R2 (never from pokemonasia), resizes it so its longest side is 128px, encodes WebP with alpha, uploads it as `expansion-sets/<id>.<hash8>.webp` (`<hash8>` is the first 8 hex characters of the output's SHA-256, so the `immutable` cache stays safe if the size ever changes) and saves the key in `expansion_sets.cover_key`. The original object and `image_key` stay untouched as the source for a later re-size. It shells out to `vips` (`apt install libvips-tools`, `brew install vips`) and exits with a clear message before touching anything if `vips` is missing. It needs the four `R2_*` settings, logs progress per row, retries failed rows on the next run, and exits 1 if any row failed. A second run changes nothing. The ingester and `host-images` are unchanged: they host the original and leave `cover_key` empty, so `presize-images` is the second step after them.

Every Expansion Set `imageUrl` the API returns (`GET /catalog/series`, the card search's embedded `expansionSet`, the expansion set facet options) is built from `cover_key`, empty when it is empty, with no fallback to `image_key` or the source address. The frontend's `setCover` Cloudflare rewrite is gone: `ExpansionSetTile` loads `imageUrl` directly and renders text-only when it is empty or fails to load.

Rollout order for Expansion Set covers:

1. Apply the migration that adds `expansion_sets.cover_key` with `make job` against the production database (additive: empty, `not null default ''`; the running API keeps reading `image_key`).
2. Run `make presize-images` against the production database and bucket, and confirm every row with an `image_key` now has a `cover_key`.
3. Deploy the API and frontend that read `cover_key`. Deploying before step 2 shows every set text-only until the command has run.
